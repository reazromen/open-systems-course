Debugging with GDB, JTAG, and Breakpoints

GDB controls a debugging session; a target server or probe communicates with the MCU, while the ELF supplies symbols and source mappings. The ELF must match the running firmware. Breakpoints expose control flow but halting can change watchdogs, peripherals, and timing. Optimized builds may inline functions or remove variables. Check board-specific JTAG/SWD pinout, target voltage, and shared pins before attaching a probe.

Learning Objectives

  • Explain how GDB, the debug probe, and the matching ELF work together.
  • Set a breakpoint and inspect the call stack and relevant variables.
  • Identify how optimization and halting can distort observed behavior.

Practical Reasoning

Build with debug symbols; set a breakpoint; inspect call stack and variables; compare debug and optimized builds; record the exact ELF and firmware revision.

Practical Lab

  1. Prerequisites: a supported debug probe, compatible target wiring, and the ELF from the exact firmware build. Verify voltage and pin mapping before connecting the probe.
  2. Start the target server/debug session using the board vendor’s documented procedure and load the matching ELF.
  3. Set one breakpoint in a known function; inspect the call stack and a variable with a known expected value.
  4. Repeat with an optimized build and note any inlined or unavailable variables; do not use halted timing as a real-time measurement.
  5. Disconnect the probe safely and record firmware revision, probe, configuration, and findings.

Expected result: A debugging record showing the matching ELF, a breakpoint, inspected call stack/variable, and the limitations of halted execution.

Troubleshooting: If symbols or source lines look wrong, verify that the ELF and flashed firmware share the same build identity and check probe wiring/target voltage.

Common Pitfall

Do not use symbols from a different build or treat halted execution as representative timing.

Check Your Understanding

1. Why must the ELF match?

Symbols and addresses are build-specific.

2. Why can breakpoints alter behavior?

Halting changes scheduling and peripheral timing.

3. What does a probe provide?

A hardware path for halting, stepping, and inspecting the target.

Key Takeaways

  • The ELF and running firmware must come from the same build.
  • Breakpoints can change timing and peripheral behavior.
  • Use target-specific probe documentation and voltage checks.
