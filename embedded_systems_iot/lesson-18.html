Flashing, Boot Modes, and the Serial Console

Flashing writes built images to nonvolatile memory; building, flashing, resetting, and monitoring are separate operations. Use the SDK-generated flash command because offsets depend on target and partition configuration. Boot straps may be sampled during reset, and sequences vary by board. Confirm the cable, port, baud rate, and exclusive serial-port ownership. Capture from power-on and identify ROM, bootloader, and application stages where possible.

Learning Objectives

  • Distinguish compiling, flashing, resetting, and serial monitoring.
  • Use the SDK-generated flash command for the selected target and partition table.
  • Interpret boot output to identify the last successful startup stage.

Practical Reasoning

Build for the exact target; save build and flash logs; run the generated command; capture boot output; document port recovery.

Practical Lab

  1. Record the exact board revision, target, SDK version, and build configuration; confirm the USB cable and serial port.
  2. Build the project and save the command output and generated flash command.
  3. Use the SDK-generated command to flash; do not copy offsets or boot-button sequences from another board.
  4. Capture serial output from reset and mark the ROM, bootloader, and application stages that appear.
  5. If flashing fails, check port ownership, cable, target configuration, baud rate, and board-specific boot instructions one at a time.

Expected result: A saved build/flash log and boot capture identifying the last startup stage that succeeded.

Common Pitfall

Never guess image offsets or assume boot-button sequences are universal.

Check Your Understanding

1. Why are build and flash different?

Build creates artifacts; flashing transfers them to device storage.

2. What causes garbled output?

Common causes include baud mismatch, wrong port, or configuration issues.

3. Why capture the full boot log?

It identifies the last startup stage that worked.

Key Takeaways

  • Build, flash, reset, and monitor are separate operations.
  • Use generated commands and the exact target configuration.
  • Boot logs narrow diagnosis to the last successful startup stage.
