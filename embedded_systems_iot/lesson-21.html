GPIO Inputs, Pull Resistors, and Debouncing

An undriven input can float. Pull-ups bias a line high and pull-downs low; internal pulls have limitations. A button wired to ground with a pull-up is active-low: high means released, low means pressed. Mechanical contacts bounce and may generate multiple edges per press. Debouncing requires a stable level over an interval or a periodic state machine. An interrupt does not remove bounce; it can signal a worker that validates the state later.

Learning Objectives

  • Explain floating inputs, pull resistors, and active-low button wiring.
  • Implement time-based debouncing without blocking unrelated work.
  • Test short, long, and repeated presses and document observed transitions.

Practical Reasoning

Verify safe GPIO voltage and pull configuration; log transitions with timestamps; implement stable-for-N-milliseconds debounce without blocking delays; test short, long, and repeated presses.

Practical Lab

  1. Check the board documentation for a safe GPIO and valid logic voltage; wire a button using the documented pull-up or pull-down arrangement with power disconnected.
  2. Log raw input transitions with timestamps before debouncing.
  3. Implement a stable-for-a-defined-interval state machine; avoid a long blocking delay in the main loop or task.
  4. Test at least ten short presses, several long presses, and rapid repeated presses; compare raw edges with accepted press events.
  5. Expected result: one accepted event per deliberate press under the test conditions. If readings float, verify wiring and pull configuration before changing software.

Common Pitfall

Never leave an input floating or assume one press produces one clean edge.

Check Your Understanding

1. What does a pull-up do?

It gives an undriven input a defined high level.

2. Why can one press create multiple edges?

Mechanical contacts bounce.

3. Why debounce without a long delay?

Other firmware work continues while the state is validated.

Key Takeaways

  • Pull resistors define idle input levels; they do not eliminate bounce.
  • Debounce validates stable state without blocking unrelated work.
  • Confirm voltage and pin limits before wiring.
