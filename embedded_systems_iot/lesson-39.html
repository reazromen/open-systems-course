Heap, Static Allocation, and Memory Failure

Understand embedded memory budgets and choose allocation strategies that remain predictable over long runtimes.

Learning Objectives

  • Compare static, stack, and heap allocation.
  • Recognize fragmentation, leaks, and allocation failure.
  • Design bounded memory use and explicit failure handling.

Memory regions

Static storage is reserved for the program lifetime; task stacks are bounded per execution context; heap allocation requests memory dynamically. RAM regions, external RAM, DMA-capable memory, and alignment constraints depend on the MCU and SDK.

Dynamic allocation trade-offs

Heap allocation is flexible but can fail, fragment memory, and complicate lifetime reasoning. Repeated allocation/free patterns may behave differently over long runtimes than at startup. A non-null pointer is not enough if requested size or alignment is wrong.

Bounded alternatives

Static buffers, fixed-size pools, rings, and bounded queues make memory use easier to budget, but still need capacity and overflow policies. Avoid large local arrays on small task stacks. Place long-lived buffers in suitable memory and check DMA/peripheral requirements.

Failure is a normal path

Check allocation results and never continue with invalid pointers. Decide whether to reject a request, reduce optional work, reuse a buffer, or enter a controlled fault state. Total free memory can hide fragmentation; when supported, monitor both free heap and largest allocatable block.

Practical Lab

  1. Inventory major static buffers, task stacks, queues, and dynamic allocations.
  2. Calculate a rough RAM budget with capacity assumptions and margin.
  3. Force allocation failure in a host test or controlled harness and verify the error path.
  4. Record free heap and largest block where supported; explain the difference.

Expected result: A memory budget listing static buffers, stacks, queues, heap use, capacities, and a justified safety margin.

Troubleshooting: Measure on the intended target where possible; host estimates do not establish MCU memory use, and do not force allocation failure on production hardware.

Common Pitfall

Do not assume allocation always succeeds or that total free heap proves one large allocation will fit.

Check Your Understanding

1. How can fragmentation matter?

Free memory may exist but not as a sufficiently large contiguous block.

2. Why use fixed-size pools?

They can make memory use and allocation behavior more predictable.

3. What should happen after allocation failure?

Handle it explicitly without using an invalid pointer.

Key Takeaways

  • Compare static, stack, and heap allocation.
  • Recognize fragmentation, leaks, and allocation failure.
  • Design bounded memory use and explicit failure handling.
