Practical Lab

  1. Choose a parser or state machine; write host tests for valid, invalid, boundary, and timeout cases; add a hardware integration checklist and secret-free log format.

Common Pitfall

Treating passing host tests as proof of peripheral timing, electrical behavior, or target correctness.

Check Your Understanding

1. What do host tests cover well?

Pure logic such as parsing, state machines, and calculations.

2. Why are hardware tests needed?

They validate real peripherals, timing, and target integration.

3. What belongs in a failure report?

Revision, SDK/target/configuration, steps, expected and actual result, and logs.

Key Takeaways

  • Separate host and hardware tests.
  • design actionable logs.
