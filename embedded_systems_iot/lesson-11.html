Integer Width, Signedness, and Overflow

Learn how C represents numbers on embedded targets and why assumptions about integer ranges cause firmware bugs.

Learning Objectives

By the end of this lesson, you should be able to:

  • Compare fixed-width integer types and their ranges.
  • Explain signed and unsigned arithmetic and overflow risks.
  • Choose explicit types for registers, counters, and serialized data.

Numbers occupy finite storage

Embedded C runs on targets with finite memory and hardware-defined integer widths. The type uint8_t represents an unsigned 8-bit value when the implementation provides the exact-width type; its range is 0–255. int8_t is a signed 8-bit type with range −128–127 on systems providing that type. Similar fixed-width types are available in <stdint.h>.

Plain int, long, and pointer sizes depend on the implementation and ABI. Do not assume they have the same width across every MCU, host compiler, or toolchain. Use types based on the value range and interface requirements.

Unsigned wraparound

Unsigned integer arithmetic is defined modulo 2ᴺ for an N-bit type. For an 8-bit unsigned value, incrementing 255 wraps to 0 after the value is converted back to that type. This can be useful for counters, but can also break timeout logic, array bounds, and length checks if it is not intentional.

#include <stddef.h>
#include <stdint.h>

enum { ERROR_TOO_LARGE = -1 };

uint8_t demonstrate_wraparound(void)
{
    uint8_t count = 255;
    count = (uint8_t)(count + 1);  // becomes 0
    return count;
}

int validate_length(size_t length, size_t buffer_capacity)
{
    if (length > buffer_capacity) {
        return ERROR_TOO_LARGE;
    }
    return 0;
}

The second example is only a starting point; signedness and the types used in the comparison must still be checked. Avoid arithmetic that can overflow before a bounds check is performed.

Signedness traps

Mixing signed and unsigned values can convert a negative value into a very large unsigned value. Comparisons may therefore behave differently from what a reader expects. Integer promotions also mean that a small integer type may be promoted to int during an expression, so reason about the expression's actual types, not only the variable declarations.

Choosing types intentionally

  • Use fixed-width types for hardware registers and protocol fields when the specification requires a specific width.
  • Use size_t for object sizes and array indexing interfaces where appropriate.
  • Use signed types when negative values are meaningful.
  • Check range before narrowing a larger value to a smaller type.
  • Use format macros such as PRIu32 from <inttypes.h> when portable formatting of fixed-width values is required.

Practical Lab

Write a small host-side C program that demonstrates the range of uint8_t, the difference between signed and unsigned comparisons, and a checked conversion from uint32_t to uint8_t. Compile with warnings enabled (for example, -Wall -Wextra -Wconversion where supported) and explain every warning rather than simply suppressing it.

Expected result: A host C test that prints or asserts the uint8_t range, demonstrates signedness behavior, and rejects an out-of-range conversion before narrowing.

Troubleshooting: Compile with warnings enabled and inspect the exact types in comparisons; do not “fix” warnings by blindly casting or suppressing them.

Common Pitfall

Assuming integer widths are universal or checking a value only after a narrowing conversion. Validate ranges before converting and be explicit about signedness.

Check Your Understanding

1. What is the range of uint8_t?

0 through 255, when the exact-width unsigned 8-bit type is provided.

2. Why can a negative signed value behave unexpectedly in an unsigned comparison?

Usual arithmetic conversions may convert it to an unsigned type, producing a large non-negative value.

3. Why use fixed-width types for protocol fields?

The protocol defines exact bit widths, while generic C integer types can vary across implementations.

Key Takeaways

  • Compare fixed-width integer types and their ranges.
  • Explain signed and unsigned arithmetic and overflow risks.
  • Choose explicit types for registers, counters, and serialized data.
