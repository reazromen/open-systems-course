ISRs, Deferred Work, and Race Conditions

A Boolean flag can coalesce events; a counter preserves counts up to capacity; a queue preserves ordered records; a ring buffer carries streams. Choose based on what cannot be lost and define overflow behavior. An ISR should use only documented ISR-safe APIs. volatile affects compiler treatment but does not make compound operations atomic or synchronize fields. Buffer handoffs need explicit ownership, lifetime, capacity, and producer/consumer rules.

Learning Objectives

  • Choose a flag, counter, queue, or ring buffer based on event-loss requirements.
  • Explain why volatile does not provide atomicity or synchronization.
  • Define ISR-safe handoff, buffer ownership, capacity, and overflow behavior.

Core Concepts

A Boolean flag can coalesce events; a counter preserves counts up to capacity; a queue preserves ordered records; a ring buffer carries streams. Choose based on what cannot be lost and define overflow behavior. An ISR should use only documented ISR-safe APIs. volatile affects compiler treatment but does not make compound operations atomic or synchronize fields. Buffer handoffs need explicit ownership, lifetime, capacity, and producer/consumer rules.

Practical Reasoning

Design ISR → queue/notification → worker task; justify event coalescing; define queue-full handling; explain why volatile cannot prevent a lost update.

Practical Lab

  1. Choose an event source and state whether every event must be preserved or whether coalescing is acceptable.
  2. Implement a flag, counter, queue, or ring buffer that matches that requirement using the platform’s documented ISR-safe APIs.
  3. Define producer/consumer ownership, buffer capacity, synchronization, and the action taken when the buffer fills.
  4. Generate a burst of events and compare produced, processed, and dropped counts; repeat under load.
  5. Expected result: accounting explains all events, including any intentional drops; do not rely on volatile alone for atomic increments or cross-task synchronization.

Troubleshooting: If counts diverge unexpectedly, inspect synchronization, buffer ownership/capacity, overflow policy, and whether every API is ISR-safe.

Common Pitfall

volatile is not a lock, and a full queue needs an explicit overflow policy.

Check Your Understanding

1. When is a Boolean flag appropriate?

When repeated events may intentionally collapse.

2. Why is volatile insufficient for a counter?

Increment is read-modify-write and can interleave.

3. What must buffer handoff specify?

Ownership, lifetime, capacity, and overflow behavior.

Key Takeaways

  • Choose a handoff primitive based on whether events may be lost or coalesced.
  • volatile is not a synchronization primitive.
  • Define ownership, capacity, overflow, and ISR-safe behavior.
