FreeRTOS on ESP32 and Dual-Core Considerations

Understand task placement, core affinity, shared memory, and synchronization on dual-core ESP32 targets.

Learning Objectives

  • Explain concurrent execution.
  • Distinguish scheduling from mutual exclusion.
  • Protect shared invariants.

Tasks and core placement

FreeRTOS tasks are schedulable execution contexts, not automatically separate processors. On dual-core ESP32 targets, task affinity may constrain where a task runs, but pinning tasks does not by itself make shared data safe. Confirm the exact target and ESP-IDF configuration before relying on core-specific behavior.

Priorities and blocking

A ready higher-priority task can pre-empt a lower-priority task. Blocking on a queue, semaphore, or delay allows other eligible tasks to run; busy-waiting can waste CPU time and starve useful work. Set priorities from deadlines and dependencies rather than from perceived importance alone.

Shared resources and synchronization

Tasks on different cores can access shared memory concurrently. Protect invariants with an appropriate mutex, queue, atomic operation, or single-owner task. A critical section should be short and use the API intended for the calling context; do not call blocking APIs from an interrupt handler.

Measure before optimizing

Observe stack high-water marks, runtime, queue depth, and deadline behavior under realistic load. Treat affinity as a measured design choice, not a default performance fix. Include overload and recovery behavior in tests.

Practical Lab

  1. Create two tasks sharing a counter or buffer; compare unsynchronized behavior with a suitable synchronization primitive and explain why core pinning alone does not fix the race.

Common Pitfall

Assuming core affinity or disabling local interrupts protects shared state across cores.

Check Your Understanding

1. Does core pinning synchronize shared data?

No. Concurrent access still requires ownership and synchronization.

2. Why is suspending scheduling on one core insufficient?

The other core may still access shared memory.

3. When should affinity be used?

When a measured constraint justifies it.

Key Takeaways

  • Explain concurrent execution.
  • Distinguish scheduling from mutual exclusion.
  • Protect shared invariants.
