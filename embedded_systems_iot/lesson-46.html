Wi-Fi Provisioning, DHCP, DNS, and Reconnect

Trace a device from network credentials to usable connectivity and implement bounded recovery.

Learning Objectives

  • Distinguish association, IP, DNS, and service reachability.
  • Model connection states.
  • Bound retries.

Provisioning and network identity

Provisioning supplies network credentials and device configuration. Provide a deliberate setup path, validate input, and avoid exposing credentials in logs or debug endpoints. The device should have a documented behavior when credentials are absent or rejected.

DHCP and DNS

DHCP normally provides network configuration such as an address, gateway, and DNS servers. DNS resolves a service name to an address; it can fail even when Wi-Fi association succeeds. Diagnose association, address assignment, name resolution, and application connection as separate stages.

Reconnect state machine

Model states such as disconnected, associating, configured, resolving, connected, and backing off. Use bounded retries with backoff and jitter rather than retrying continuously. Preserve local functionality while offline where the product requirements allow it.

Diagnostics and recovery

Record state transitions and error categories without logging secrets. Test unavailable access points, wrong credentials, DNS failure, router restarts, and temporary service outages. Define when the device retries automatically and when user intervention is required.

Practical Lab

  1. Draw states from credentials through association, DHCP, DNS, and service health; simulate missing AP and DNS failure; verify bounded retries without logging credentials.

Common Pitfall

Treating Wi-Fi association as proof that DNS and the cloud service are reachable.

Check Your Understanding

1. What does DHCP provide?

Network configuration such as an IP address.

2. Does Wi-Fi association prove DNS works?

No; association, IP, DNS, and service reachability are separate.

3. Why use bounded backoff?

To avoid rapid retry loops that consume power and overload networks.

Key Takeaways

  • Distinguish association, IP, DNS, and service reachability.
  • Model connection states.
  • Bound retries.
