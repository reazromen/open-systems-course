Switches, LEDs, and Safe GPIO Circuits

Translate simple components into safe, testable digital inputs and outputs.

Learning Objectives

By the end of this lesson, you should be able to:

  • Wire an LED output with current limiting.
  • Explain active-high and active-low button circuits.
  • Identify basic GPIO protection and startup-state considerations.

GPIO is an interface, not a complete circuit

A GPIO pin can be configured as an input or output, but the external circuit determines what the pin electrically sees and controls. Before wiring, verify the board voltage, the pin's allowed functions, its startup behavior, and whether the board already connects that pin to an LED, button, boot strap, or peripheral.

LED output

An LED needs current limiting. In a simple circuit, connect GPIO → resistor → LED → ground, with the LED polarity correct. In that arrangement the output is typically active-high: setting the pin high turns the LED on. Reversing the logic and wiring can make an output active-low. Onboard LEDs may be active-low or connected through additional circuitry, so check the schematic rather than assuming.

Button input

A button is a mechanical contact. A pull-up or pull-down resistor establishes a defined idle level, while pressing the button changes the level. A physical switch can bounce for a few milliseconds, producing several rapid transitions. Software debouncing can accept a state only after it remains stable for a chosen interval, or use a time-based state machine that avoids blocking unrelated work.

Startup and safe states

During reset and boot, a pin may be high-impedance, have a special boot function, or briefly change behavior. If an output controls a relay, lock, motor, heater, or other consequential load, the safe state should be enforced electrically where possible and validated in firmware. Never rely on a late application initialization to prevent an unsafe pulse if the hardware can energize earlier.

A useful test sequence

  1. Check the schematic and pinout.
  2. Power the board without the external load and verify the pin configuration.
  3. Use a current-limited indicator circuit first.
  4. Measure the signal relative to ground.
  5. Test reset, boot, disconnect, and fault conditions.

Practical Lab

On a simulator or a verified 3.3 V development board, build one LED output and one button input.

  1. Record the exact GPIOs and board revision.
  2. Use a series resistor for the LED and a defined pull-up or pull-down for the button.
  3. Implement a simple pressed/released state and indicator response.
  4. Observe the behavior during reset and after disconnecting the button signal.
  5. Add debouncing in the next iteration; do not assume the first electrical transition is stable.

Common Pitfall

Copying a GPIO example without checking the board schematic, pin reservations, active polarity, and boot behavior. The same code can behave differently on different boards.

Check Your Understanding

1. Why does an LED usually need a resistor?

It limits current to protect the LED and GPIO and keeps the circuit within component ratings.

2. What is switch bounce?

A mechanical contact can produce several rapid electrical transitions around a single press or release.

3. Why test a pin during reset as well as normal operation?

Its startup configuration may differ from the application's configured state and could briefly affect connected hardware.

Key Takeaways

  • Wire an LED output with current limiting.
  • Explain active-high and active-low button circuits.
  • Identify basic GPIO protection and startup-state considerations.
