From Superloop to RTOS

Choose a firmware execution model based on workload, latency, concurrency, and maintainability—not fashion.

Learning Objectives

  • Explain a superloop and its scaling limits.
  • Describe what an RTOS scheduler adds.
  • Choose when to remain simple and when to introduce tasks.

Superloop model

A superloop repeatedly calls functions for inputs, control, communication, and status. It is easy to inspect and works when each step is bounded. A long blocking operation delays every function scheduled later.

Event-driven alternatives

A cooperative event loop processes ready events without necessarily using a preemptive RTOS. Interrupts can capture urgent events while normal code handles them later. This can provide sufficient structure with less stack and synchronization complexity than multiple tasks.

What an RTOS adds

An RTOS can run tasks with separate stacks, priorities, blocking waits, and synchronization primitives. It helps separate activities with different timing needs, but adds context switches, memory cost, shared-state risks, and configuration complexity.

Make the migration decision

List activities, event rates, worst-case execution, blocking calls, and deadlines. If one bounded loop meets requirements, keep it. Introduce tasks when independent blocking operations or explicit scheduling needs justify them; define ownership and communication first.

Practical Lab

  1. Draw a superloop for sensor sampling, communication, and status indication.
  2. Mark blocking operations and estimate how long each delays the others.
  3. Sketch an event-driven or RTOS design only for activities that need independent progress.
  4. Compare complexity, stack usage, timing, and testability; justify the simplest adequate model.

Common Pitfall

Do not introduce an RTOS solely because a project has several features; concurrency adds failure modes and resource costs.

Check Your Understanding

1. What is a superloop's main timing risk?

One long or blocking step delays all later work.

2. Does an RTOS make shared state safe automatically?

No. Shared data still needs explicit ownership and synchronization.

3. When should you keep a superloop?

When bounded work and timing requirements can be met simply and reliably.

Key Takeaways

  • Explain a superloop and its scaling limits.
  • Describe what an RTOS scheduler adds.
  • Choose when to remain simple and when to introduce tasks.
