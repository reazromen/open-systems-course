Bitwise Operations and Register Masks

Read and modify individual hardware bits without accidentally changing unrelated register fields.

Learning Objectives

By the end of this lesson, you should be able to:

  • Use bit masks with AND, OR, XOR, and NOT.
  • Set, clear, and test a specific bit safely.
  • Explain why register access requires the target reference manual.

Bits are often the hardware interface

Peripheral registers frequently contain multiple control flags packed into one integer. A bit mask identifies the bit or field you want to inspect or modify. In C, & is bitwise AND, | is bitwise OR, ^ is bitwise XOR, and ~ is bitwise NOT. These operators differ from logical operators && and ||.

Common patterns

#include <stdint.h>

uint32_t demonstrate_bit_operations(void)
{
    uint32_t reg = 0;
    const uint32_t BIT_3 = (uint32_t)1u << 3;

    reg |= BIT_3;          // set bit 3
    reg &= ~BIT_3;         // clear bit 3
    reg ^= BIT_3;          // toggle bit 3
    if ((reg & BIT_3) != 0u) {
        // bit 3 is set
    }
    return reg;
}

These patterns illustrate ordinary integer manipulation. A real peripheral register may have special write-one-to-clear bits, reserved fields, read side effects, or restrictions on read-modify-write operations. Follow the target's reference manual and vendor API.

Why masks matter

Suppose a register holds enable, mode, and interrupt flags. Assigning a whole value just to enable one feature can overwrite the other fields. A masked update can preserve unrelated bits—but only if the hardware register semantics permit read-modify-write. Some registers require writing a carefully constructed value or using atomic set/clear aliases.

Shifts and type width

Use an unsigned value of the intended width for masks. Shifting by an amount equal to or greater than the operand width is undefined in C, and shifting signed values can introduce additional problems. A mask expression should make its width and intent obvious.

Prefer documented driver APIs when available

Direct register manipulation is useful for understanding hardware and working in low-level environments, but production code should normally use the supported SDK driver unless there is a documented reason not to. Vendor drivers encode target-specific details and may provide synchronization or validation that a raw register write does not.

Practical Lab

  1. Write a host-side C program with an 8-bit value and functions to set, clear, toggle, and test a chosen bit.
  2. Print the value in binary or hexadecimal before and after each operation.
  3. Test boundary bit positions and explain the width of every mask.
  4. Open the reference manual for a target peripheral and identify whether its status flags use ordinary write semantics or special clearing rules.

Expected result: A bit-mask test that shows the chosen bit before and after set, clear, toggle, and test operations.

Troubleshooting: Check the shift count is within the operand width and use parentheses to make mask operations explicit.

Common Pitfall

Using a read-modify-write operation on a hardware register without checking its semantics. Some flags clear when written as one, and some registers must be accessed through dedicated set/clear mechanisms.

Check Your Understanding

1. How do you set bit 5 without changing other ordinary bits?

Use a mask and bitwise OR, such as `reg |= (1u << 5)`, with an appropriate unsigned type and valid shift.

2. What is the difference between & and && in C?

`&` operates on bits; `&&` evaluates logical truth and produces a logical result.

3. Why can a correct-looking register mask still be unsafe?

The register may have special write semantics, side effects, reserved bits, or concurrency requirements documented by the hardware vendor.

Key Takeaways

  • Use bit masks with AND, OR, XOR, and NOT.
  • Set, clear, and test a specific bit safely.
  • Explain why register access requires the target reference manual.
