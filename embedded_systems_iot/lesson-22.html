Timers, PWM, and Scheduling Without delay()

A blocking delay stops the current context from doing other work; a timebase lets code compare elapsed time while handling events. Timer resolution and range depend on the MCU and SDK. PWM controls the active fraction of each period; frequency and duty cycle are separate. PWM is not a power stage for motors or other loads. Use monotonic time and explicit deadlines, then decide whether missed periods are caught up, coalesced, or skipped.

Learning Objectives

  • Distinguish timer periods, elapsed time, PWM frequency, and duty cycle.
  • Implement a nonblocking periodic action using a monotonic timebase.
  • Define and test behavior when a scheduled deadline is missed.

Core Concepts

A blocking delay stops the current context from doing other work; a timebase lets code compare elapsed time while handling events. Timer resolution and range depend on the MCU and SDK. PWM controls the active fraction of each period; frequency and duty cycle are separate. PWM is not a power stage for motors or other loads. Use monotonic time and explicit deadlines, then decide whether missed periods are caught up, coalesced, or skipped.

Practical Reasoning

Blink an LED with nonblocking periodic updates; measure intervals; vary PWM duty cycle at fixed frequency; simulate delayed processing and record missed-deadline behavior.

Practical Lab

  1. Choose an LED output documented as safe for the board and use a current-limiting resistor; disconnect power while wiring.
  2. Implement periodic LED changes using monotonic elapsed time rather than a long blocking delay.
  3. If PWM hardware is available, hold frequency constant while changing duty cycle and observe brightness or measure the signal.
  4. Introduce a controlled processing delay and record whether the schedule catches up, coalesces, or skips missed periods.
  5. Expected result: recorded period/jitter observations and an explicit missed-deadline policy; do not connect a motor or other high-current load directly to GPIO.

Common Pitfall

Do not confuse PWM duty cycle with frequency or block the event loop with long delays.

Check Your Understanding

1. What is PWM duty cycle?

The fraction of a period the output is active.

2. Why use monotonic time?

Wall-clock corrections do not disrupt elapsed-time deadlines.

3. What must scheduling decide?

Whether to catch up, coalesce, or skip missed periods.

Key Takeaways

  • Use monotonic time for elapsed-time scheduling.
  • PWM frequency and duty cycle describe different properties.
  • Define what happens when a deadline is missed.
