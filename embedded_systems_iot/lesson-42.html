Package related code behind explicit interfaces and dependencies so hardware access stays testable and maintainable.

  • declare dependencies.

Practical Lab

  1. Inspect a project's component manifest and public headers; move one reusable helper into a component, declare dependencies, build, and document its API and error contract.

Common Pitfall

Making every file a component without defining ownership or interfaces creates structure without modularity.

Check Your Understanding

1. What belongs in a public component interface?

Only stable functions, types, and contracts needed by consumers.

2. Why separate driver and application policy?

It improves reuse and allows application behavior to be tested independently.

3. What do declared dependencies improve?

Build clarity, interface visibility, and maintainability.

Key Takeaways

  • Identify public interfaces.
  • declare dependencies.
  • separate application policy from hardware-specific code..
